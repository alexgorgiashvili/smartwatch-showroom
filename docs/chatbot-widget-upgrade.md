# Website chatbot: conversation-based upgrade

## Scope and release state

The website widget keeps its existing `/chatbot` request and response contract. `CHATBOT_WIDGET_V2_PERCENT=0` is the safe default. The candidate cohort alone receives the versioned policy context and `CHATBOT_WIDGET_V2_MODEL`; Messenger, Instagram, and WhatsApp continue to use `CHATBOT_SUPERVISOR_MODEL`. No production DB migration, policy sync, Meta permission change, or deployment is part of this local package.

The historical conversation audit has a single purpose: count interests and reply patterns and generate controlled, anonymous evaluation questions. Raw text, contact information, attachments, platform IDs, and page reply text must not be committed or submitted as evaluation prompts. Page replies are candidate evidence only; pricing, availability, warranties, and policies require a public or owner-approved source.

## Files and evidence

- `database/data/chatbot_widget_knowledge.json`: versioned widget-only public facts. Price and stock are absent; they must come from live SQL product context.
- `database/data/chatbot_conversation_audit.json`: aggregate topic, reply-signal, date-span, and source-coverage report generated by `chatbot:audit-conversations`.
- `database/data/chatbot_conversation_scenarios.json`: frozen synthetic Georgian questions derived from observed topic counts. They contain no raw customer words or source identifiers. These are **not automatically graded answers**.
- `database/data/chatbot_policy_scenarios.json`: 20 additional risk-focused, synthetic questions linked to the published terms. The `facts` and `must_not_claim` tags are grading criteria for a later independent review; no automatic judgment is implied.
- `PairedModelBenchmarkService`: requires actual usage, measured latency, at least 100 paired rubric-graded cases, and every release gate before returning `candidate_meets_gates`. Without a trustworthy offline rubric it returns `insufficient_evidence`.
- `database/data/chatbot_model_only_benchmark.json`: 120-pair model-only metrics from controlled synthetic prompts with identical public context. It includes de-identified case IDs and token/latency data but no generated responses.

### Audit snapshot, 2026-09-26

The read-only audit covered 416 Messenger conversations and 4,909 Graph message records, with no conversation truncated at the 1,000-message cap. The local store has 296 messages; 11 additional verified webhook echoes were inspected. Messenger spans 2025-12-16 through 2026-09-25. Instagram's Page probe returned no confirmed history, and its configured Instagram token returned HTTP 401 / Meta code 190; only 32 older local Instagram message records were available. WhatsApp has no configured history reader in this integration; only 2 older local customer message records were available. 227 Messenger records lacked text (for example, attachment-only events); the audit does not extract attachments.

Customer interest signals, including local channels, were price 460, connectivity/SIM 117, stock 82, delivery 45, calling/video 40, and other classified topics. There were 1,329 unclassified text messages; 361 of those look like questions, so topic coverage is incomplete. 1,176 customer messages were 20 characters or shorter. Business Page/admin reply signals included price 839, delivery 567, contact request 452, payment 364, and availability 231. Signals can overlap within one message and do not establish that the account owner authored a reply. Among the 122 stored widget bot messages, 7 matched known fallback-like wording; this is a text heuristic, not a measured error rate.

The audit generated 120 unique controlled questions from observed intents, and the policy supplement adds 20. A local scanner found no email, phone, URL, source hash, platform message ID, or raw-message field in the observed set. The 20 policy cases are linked to the public terms. The 120 observed cases lack independently verified answer rubrics, so the combined set cannot establish a release quality score yet.

Knowledge deliberately not promoted from the conversations includes one-off prices or discounts, availability promises, exact delivery dates, device capabilities without a matching product specification, and replies whose human author cannot be established. The observed set is weighted toward demand (67 price, 16 connectivity, 11 stock; 18 website and 102 Messenger examples). The policy supplement covers payment and exchange risks, but response judgments and product-specific evidence still need review before the release gate can be considered.

The audit command makes only Meta GET requests and local DB SELECTs. It can write only the two de-identified JSON outputs in its selected `--output-dir`. Its caps are `--max-conversations`, `--max-messages`, and `--max-meta-requests`. Run it in a secure local checkout with existing credentials; never export raw transcripts into Git, a report, or a model prompt.

### Model-only exploratory result, 2026-09-26

All 120 observed scenarios completed for both `gpt-4.1-mini` and `gpt-6-luna` with provider token usage. Baseline generation cost was $0.0301748, candidate cost $0.0065201 (about 78% lower). Model-only p95 latency was 2,347 ms versus 1,962 ms. A weak text screen detected Georgian characters in 120/120 responses for each model; it flagged 9 versus 2 possible unsupported price/stock statements, which require manual review and may include false positives. No answer received an independent grounded-quality grade. The benchmark correctly reports `insufficient_evidence` and no cost per successful answer. Total measured comparison cost was $0.0366949; one earlier two-model API smoke test cost about $0.0000503, for approximately $0.0367452 combined, below the $3 authorization.

## Launch gates

Keep the candidate disabled unless the **same frozen cases** show all of the following:

1. At least 100 pairs have real token usage, measured latency, and independent rubric judgments for groundedness, Georgian, critical unsupported claims, and fallback suitability.
2. Grounded-success rate improves by at least 5 percentage points.
3. No candidate answer makes an unverified critical price, stock, or policy promise.
4. Georgian pass rate and p95 end-to-end latency do not worsen.
5. Full API cost per successful answer falls by at least 20%, including helper model calls, embeddings, reranking, retries, and judging when used.
6. The evaluation spend is recorded and stays at or below $3 in total. Missing usage or a budget overrun makes the result unverified.

Model-only smoke tests are useful for endpoint compatibility and estimated generation cost. They do not establish end-to-end quality or cost and cannot pass these gates.

## Approved rollout procedure

After the owner approves deployment and the release gates pass:

1. Confirm the final merged checkout includes the site's other active stock/inventory changes. Run the local tests with an isolated temporary SQLite database and review the audit for personal data before any remote action.
2. Deploy code with `CHATBOT_WIDGET_V2_PERCENT=0` and `CHATBOT_WIDGET_V2_MODEL=gpt-6-luna`. Ensure no shared RAG/DB policy sync runs as part of this widget release.
3. Enable non-payload widget traces if needed (`CHATBOT_WIDGET_TRACE_ENABLED=true`, `CHATBOT_WIDGET_TRACE_INCLUDE_PAYLOADS=false`). Record cohort, model, knowledge version, real usage/cost, response latency, validation, fallback, and provider errors. Do not log prompts or provider bodies.
4. Set the widget percentage to 5, then 25, then 100 only after reviewing a meaningful sample at each stage. Measure the same quality and safety gates against the baseline cohort; check spend, p95 latency, fallback, and provider incidents.
5. To roll back, set `CHATBOT_WIDGET_V2_PERCENT=0` and reload application configuration through the normal deployment procedure. Response-cache keys are separated by channel, model, prompt, and knowledge version; a destructive cache clear is unnecessary.

## Current blockers to release

The synthetic scenarios are privacy-safe but need independent answer judgments and a full paired pipeline run. Existing legacy golden tests have matcher assertions but were authored before these conversations and do not provide independent new answer judgments. Instagram and WhatsApp historical coverage remain incomplete for the reasons in the audit snapshot. Leave the percentage at zero until the release gates are demonstrated.

The isolated branch started from the local checkout's HEAD, which was two commits behind the tracked remote main. The original checkout also has a separate in-progress inventory integration. Its `PromptBuilderService` edits are untouched here; its `ChatbotContentSyncService` stock changes and this branch's policy wording patch apply to separate hunks (`git apply --check` succeeded). Merge these streams and review the resulting live-stock behavior before deployment.

Local pure-unit tests run with an explicitly forced in-memory SQLite connection. Existing Laravel integration tests start the full migration set and currently stop at `2026_02_19_235525_add_messenger_platform_to_conversations_table.php`, which executes MySQL `ALTER TABLE ... MODIFY COLUMN ... ENUM` SQL unsupported by SQLite. No MySQL test database was used. Until a SQLite-compatible test schema or migration path is prepared, the widget's full end-to-end behavior remains unverified.

## Source controls

- Public policy: `resources/views/pages/terms.blade.php` (reviewed 2026-09-26). The 14-day term concerns *model exchange with conditions*, not an unconditional return. Delivery estimates are estimates, and same-day delivery requires confirmation.
- OpenAI model compatibility and prices: <https://developers.openai.com/api/docs/models/gpt-6-luna> and <https://developers.openai.com/api/docs/guides/latest-model> (reviewed 2026-09-26).
- OpenAI API data controls: <https://developers.openai.com/api/docs/guides/your-data>. API data is not used for training by default; abuse monitoring can retain prompts and responses for up to 30 days. Only controlled synthetic scenarios are eligible for this evaluation.
- Meta conversations endpoint: <https://www.postman.com/meta/messenger-platform-api/folder/22794852-255610cd-47f5-4f4d-b3fa-71aec360be9a>.
